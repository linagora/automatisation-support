## Environment variables

The root `.env` file controls the base domain used across all services:

| Variable       | Default             | Purpose                            |
| -------------- | ------------------- | ---------------------------------- |
| `BASE_DOMAIN`  | `twake.local`       | Domain suffix for all service URLs |
| `LDAP_BASE_DN` | `dc=twake,dc=local` | Base DN for LDAP queries           |
| `MAIL_DOMAIN`  | `twake.local`       | Email domain for user accounts     |

Changing `BASE_DOMAIN` will update all service URLs (e.g., `chat.example.com` instead of `chat.twake.local`). You will also need to update your `/etc/hosts` entries and regenerate certificates.

## Template-based configuration

Several services use **template files** that get processed by `envsubst` at startup. The `compose-wrapper.sh` script in each layer handles this substitution.

| Template                                      | Output            | Variables substituted         |
| --------------------------------------------- | ----------------- | ----------------------------- |
| `twake_auth/config/lmConf-1.json.template`    | `lmConf-1.json`   | `BASE_DOMAIN`, `LDAP_BASE_DN` |
| `twake_db/ldap/bootstrap/users.ldif.template` | `users.ldif`      | `LDAP_BASE_DN`                |
| `tmail_app/config/jmap.properties.template`   | `jmap.properties` | `BASE_DOMAIN`                 |
| `tmail_app/config/domainlist.xml.template`    | `domainlist.xml`  | `BASE_DOMAIN`                 |

:::tip
Never edit the generated files directly. Modify the `.template` files and re-run the wrapper, or the changes will be overwritten on next startup.
:::

## TLS certificates

Twake Workplace Docker uses self-signed certificates generated by `twake_auth/generate-cert.sh`. The script creates:

| File                                                | Purpose                                             |
| --------------------------------------------------- | --------------------------------------------------- |
| `twake_auth/traefik/ssl/root-ca.pem`                | Root CA certificate (import this into your browser) |
| `twake_auth/traefik/ssl/root-ca-key.pem`            | Root CA private key                                 |
| `twake_auth/traefik/ssl/twake-server-fullchain.pem` | Server certificate chain                            |
| `twake_auth/traefik/ssl/twake-server.key`           | Server private key                                  |

Certificates are auto-generated on first startup if they do not already exist. After regeneration, Traefik is automatically restarted.

### Traefik TLS configuration

Defined in `twake_auth/traefik/config/dynamic.toml`:

```toml
[tls.certificates]
  certFile = "/ssl/twake-server-fullchain.pem"
  keyFile  = "/ssl/twake-server.key"

[tls.options.default]
  minVersion = "VersionTLS12"
  sniStrict = false
```

`sniStrict = false` allows Traefik to serve the certificate for any hostname, which is necessary because a single wildcard cert covers all `*.twake.local` subdomains.

## DNS configuration

For local development, all subdomains point to `127.0.0.1` via `/etc/hosts`. The full list of required entries is in the [Getting Started](./getting-started#2-configure-dns) guide.

For a non-local deployment, configure DNS A records pointing all subdomains to the server's IP address. A wildcard DNS record (`*.twake.local`) simplifies this.

## Database credentials

Default credentials for the backing stores (intended for local/POC use only):

| Service    | Credentials                            |
| ---------- | -------------------------------------- |
| OpenLDAP   | `cn=admin,dc=twake,dc=local` / `admin` |
| PostgreSQL | `postgres` / `postgres`                |
| MongoDB    | `root` / `root`                        |
| CouchDB    | `admin` / `password`                   |
| RabbitMQ   | `admin` / `admin`                      |
| MinIO      | `minioadmin` / `minioadmin`            |
| Cozy Admin | Passphrase: `admin`                    |

:::caution
These are default credentials for a local POC. Replace them before exposing the stack to a network.
:::

## Wrapper scripts

Each layer has a `compose-wrapper.sh` that handles configuration generation and startup:

1. Runs `envsubst` on template files
2. Calls `docker compose --env-file ../.env up -d`
3. Waits for health checks to pass

The root `wrapper.sh` orchestrates all layers, enforcing startup order and dependency checks. See [Architecture](./architecture#startup-order) for the full sequence.
